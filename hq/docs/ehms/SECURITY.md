# EHMS セキュリティ・権限

## 方針
- 権限は画面の出し分けだけでなく、**データベースの行単位（RLS）で強制**する。画面を改造しても他院・他人の数字は読めない。
- 機密（給与）は Phase 1 の EHMS には入れない（スタッフ別の給与は既存の `hq_private_docs`、salary_viewer のみ）。
- API キー・データベースの認証情報はコードに書かない（Vercel の環境変数。`hq/.env.example` 参照）。ブラウザが持つのは Supabase の公開キー（anon）だけ。

## 役割（`ehms_user_roles.role`）
| 役割 | 読める数字 | 書ける数字 | その他 |
|---|---|---|---|
| owner 社長・経営者 | 全店舗＋本部 | 全店舗＋本部 | 設定・役割の変更、月次締め・解除、変更履歴 |
| gm GM | 全店舗＋本部 | 全店舗＋本部 | 店舗・事業部・科目の変更、変更履歴 |
| accounting 経理・管理部門 | 全店舗＋本部 | 全店舗＋本部 | 科目の変更、取り込み、月次締め・解除 |
| bm BM・エリアマネージャー | 担当店舗だけ | 担当店舗だけ | 本部の行は見えない |
| store_manager 院長 | 自院だけ | 自院だけ | 本部の行は見えない |
| staff 一般スタッフ | なし（Phase 2 で自分の目標・実績） | なし | |

- `ehms_user_roles` に行がない人：`clinic_staff` で role='admin' かつ salary_viewer の人だけ owner として扱う。**院の共用アカウントなど、それ以外の admin は EHMS を一切見られない**（確認済み：共用アカウント（香里園院）は0件）。
- 役割の付け外しは owner だけ。

## データの保護
- 締めた月の実績は、トリガーで追加・変更・削除を拒否（画面・取り込み・API のどこからでも）。修正は owner / accounting が締め解除してから。
- 全テーブルの変更は `ehms_audit_logs` に変更前・変更後・操作者で記録。利用者はこの表に書き込めない。
- anon（ログインしていない人）には何も許可していない。

## 確認済みの動作（2026-11-25、ロールバックしたトランザクションで確認）
- 岩永（salary_viewer の admin）→ owner、7店舗が見える
- 共用アカウント（香里園院）→ 役割なし、数字は0件
- 締めた月の実績の変更 → 拒否
- 数字の追加 → 変更履歴に記録
