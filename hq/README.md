# 株式会社Enejoy Hand 本部システム

予約管理システム（あんど整骨院の予約・会計）とは**別のシステム**です。全院・全部門を本部の立場で俯瞰して管理します。

| 部門 | できること |
|---|---|
| ダッシュボード | 全社売上・予算達成率・人件費率・新患数・スタッフ数・出店・研修・今月のやること、アラート |
| 業績 | 院別×月の予算・実績・達成率（7月始まりの年度）、全社の月別グラフ、年度累計 |
| 集客 | 新患数と来院経路（予約システムの初回来院）、集客施策の費用・獲得数・CPA |
| 人材 | 等級別の人数、院ごとの必要人数と過不足、スタッフ一覧、採用の進み具合 |
| 人員の適正判断 | 組織図（月ごとのタブ）× 年間予算（院別・月別）で、院ごとに「人員不足／適正／人員に余裕」を判定。年度12か月の一覧、計画案タブでのシミュレーション |
| 経理・事務 | 人件費42%枠（全社・院別）、毎月の定例チェック、支払い予定 |
| 教育 | 研修計画・対象等級・受講チェック、スタッフ別の受講率 |
| 組織図 | 代表 → GM → BM（エリア）→ 院長 → スタッフ（台帳から自動）、本部の部門と責任者 |
| キャリア | 等級（G1〜G6・S1〜S3）ごとの人数、一人ひとりの目指す等級・時期・育成メモ |
| 出店計画 | 新店の状態・開業予定日・初期費用・投資回収・マイルストーン |
| 年間計画 | 年度の方針・目標、月ごとの予定（カテゴリ別） |
| マンダラチャート | 会社・各院のマンダラの一覧と編集（マスの内容・月の状態） |
| データ取り込み | 院の日計表（月ごとのスプレッドシート）を読み、列ごとに業績・集客・人材・経理事務へ自動で振り分け。各部門の画面に「📥 日計表から」として院別の月合計・スタッフ別稼働を表示 |

## しくみ

```
hq/                    ← この Vercel プロジェクトの Root Directory
├ index.html           画面（ログイン・11部門）
├ hq-logic.js          集計ロジック（テスト：../test/hq.test.js）
├ api/ledger.js        GET  台帳（売上・予算・人件費・スタッフ・等級・BMエリア）
├ api/mandala.js       GET/POST 会社・院のマンダラ
├ api/intake.js        GET  日計表フォルダの一覧・日計表の中身（データ取り込み）
├ api/fit.js           GET  組織図・年間予算の2つのスプレッドシート（人員の適正判断）
└ api/_hq-auth.js      管理者だけに使わせる確認
```

- ログイン：予約管理と同じ Supabase のアカウント。`clinic_staff.role = 'admin'` の人だけが使えます（院ID・個人PASSのログインは不可）
- 本部が入力した計画・台帳：Supabase の `hq_docs` テーブル（`../sql/2026-11-11_hq_docs.sql`、管理者だけ読み書き可）
- 台帳の読み込みは予約管理と同じ処理（`../lib/`）を使います

## 人員の適正判断のしくみ

- **人員の目安** ＝ 組織図の各院の人数 × 1人あたりの目安。目安は組織図シートの下にある「院長：1100000」「施術者：900000」などの行を読みます（院長110万・副院長100万・施術者90万・時短50万・施術者（ア）30万。受付は0）
- **判定** ＝ 予算 ÷ 人員の目安。判定の幅（初期値 ±10%、画面で変更可）の中なら「適正」、上回れば「人員不足」、下回れば「人員に余裕」。過不足は施術者1人分（90万）に換算して「あと何人」で表示。実績が入っている月は「実績 ÷ 目安」も出し、人はいるのに売上が届いていない院がわかります
- **どの組織図を使うか**：タブ名の日付（「2026.7」「2026.9.17〜」「2026.12(上島入社)」）で、その月の1日時点のタブを自動で選びます。日付で始まらないタブ（「香里園出店時(理想)」など）は計画案として、画面で選ぶと全月をその配置でシミュレーションできます
- **予算のタブ**：実績が入っている最初のタブ（初期は「R8-R9 のコピー」）。画面で他のタブ（訂正用・R9-R10新案など）に切り替えられます
- シート：組織図 `ORG_SHEET_ID`、年間予算 `BUDGET_SHEET_ID`（未設定なら既定のシート）。**どちらもサービスアカウント（`GOOGLE_SERVICE_ACCOUNT_EMAIL`）に「閲覧者」で共有が必要です**
- 今月「人員不足・未配置」の院はダッシュボードのアラートにも出ます
- **組織図の問題点**：各タブの「問題点」と書いたセルの下に並ぶ文を読み込みます（例：2026.12(異動案) の K列）。文に院名（「田口山」「茨木・交野」など）があれば関係する院を自動で付け、院別判定の「理由・打ち手」にも表示します。状態（未対応／対応中／解決済み）・担当・メモ、本部で追加した問題点は `hq_docs` の `fit` に保存（シートには書き込みません）

## 人件費 × 倍率 の売上設定（人員の適正判断の中）

- スタッフ別の月平均人件費（給与明細の支給合計の平均）× 倍率（初期値3）＝ 売上設定。院ごとに合計し、その月の予算と比べて「適正／予算が低め（人件費率が高い）／予算が高め」を判定。年度12か月の一覧つき
- スタッフ別の人件費は画面で直せる（所属院・金額・見込みかどうか）。所属院を空欄にした人は全社の合計にだけ入る
- **給与は `hq_private_docs` に保存**（`../sql/2026-11-17_hq_private_docs.sql`）。`clinic_staff.salary_viewer = true` の管理者だけが読み書きでき、院の共用アカウントなどに admin が付いていても給与は見えない

## デプロイ（Vercel・初回だけ）

1. Vercel で **Add New → Project** → このリポジトリを Import
2. **Root Directory** に `hq` を指定（Framework Preset は Other）
3. 「Include files outside the root directory in the Build Step」を **ON**（既定でON。`../lib` を使うため）
4. **Environment Variables** に、予約管理のプロジェクトと同じ値を入れる
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `GOOGLE_PRIVATE_KEY`
   - （設定している場合）`SALES_SHEET_ID` / `CAREER_SHEET_ID` / `NEWPATIENT_SHEET_ID` / `PATIENT_CARE_SHEET_ID` / `ORG_SHEET_ID` / `BUDGET_SHEET_ID`
5. Deploy。以後は main にマージすると自動で更新されます

予約管理システムのサイトで `/hq/...` を開いてもトップへ戻ります（リポジトリ直下の `vercel.json` の redirects）。`.vercelignore` で `/hq` を除外すると本部システムのデプロイが空（404）になるので除外しないでください。

## データ取り込み（日計表 → 部門）のしくみ

- 日計表は月ごとのファイル（「EnejoyHand様日計表R8.11」など）。`DAILY_FOLDER_ID`（未設定なら既定のフォルダ）の中から、ファイル名の「R8.11」「2026.6」で月を判断して自動で見つける（「原本」は読まない）。フォルダの外の月は画面の「＋ URLで追加」で足せる
- **フォルダをサービスアカウント（`GOOGLE_SERVICE_ACCOUNT_EMAIL`）に「閲覧者」で共有が必要**。一覧を取るために Drive のメタデータ読み取り（drive.metadata.readonly）を使う
- 院ごとのタブ：「院名：」の行、「売上管理／母数管理／運営管理／マーケティング管理」の区分の行、その下の見出しの行、日別の行と「合計」の行を読む。「○○稼働率」タブはスタッフ別の稼働
- 列 → 部門は見出しの言葉と区分から自動（例：口コミ・キャンセル → 集客、自賠・請求・レセ → 経理事務、売上・来院 → 業績、新患 → 業績と集客）。画面で直すと `hq_docs` の `intake.map` に保存
- 単価・平均・率の列は院の合計に足さない
- **勤怠（賃金管理表）**：`WAGE_SHEET_ID`（未設定なら既定の「賃金管理表R7.4～.xlsx」。Googleスプレッドシートでも、ドライブに置いた Excel でもよい。Excel は `../lib/xlsx-lite.js` で読む）の月ごとのタブから、出勤日数・休日・有休・有給残・勤務時間・残業時間を人材の画面に表示。サーバーは A〜P 列だけを読み、H列（欠勤控除）も捨てる（基礎賃金・時給・残業代などの金額は読み込まない）。`clinic_staff.salary_viewer` の管理者だけが見られる。`?file=` で賃金管理表・キャリア台帳を丸ごと読むことはできない
- **KPIの年間推移と昨対比**：`KPI_SHEET_ID`（未設定なら既定の「店舗別KPIダッシュボード【EnejoyHand】」）の全社・院ごとのタブから、「11期」「10期」の表を読み、業績の画面に項目ごとの年間推移（今期と前期の折れ線）と昨対比（率の項目は前年差）の棒グラフ、全項目の表を表示。離反数・離反率は下がるほど良い方向として色分け。「原本」「分析」のタブは読まない
- **デイリー稼働**（新しい画面）：日付ごとに、院の営業・午前/午後の出勤者（`SHIFT_SHEET_ID`、既定「シフト管理表（原本）」）、来院数・新患・売上（日計表）、スタッフ別の稼働率（日計表の「○○稼働率」タブの日別の表）を1画面に表示。稼働率が基準未満、余剰（出勤人数×（1−稼働率））が基準以上、1人あたり来院が上限以上の院を自動でチェック。月の院×日の稼働率の一覧つき。基準は画面で変更（`hq_docs` の `daily`）。院の合計はスタッフの数字を足して出す（シートの「院全体合計」は見出しと中身がずれているため）
- **生産性と給与**（人材の画面・salary_viewer だけ）：台帳の個人売上（直近3か月の平均）÷ スタッフ別の人件費（`hq_private_docs` の `labor`）を、人件費×倍率（初期値3）と比べて「見合っている／やや不足／見合っていない」を判定
