## 承認時に決まったこと（02_設計書 §6 への回答）

| # | 項目 | 決定 |
|---|---|---|
| 1 | ログイン | 推奨どおり。院長・BM・GM・社長はメールアドレス、スタッフは既存の院ID＋院PASS＋個人PASS |
| 2 | 組織 | GM 1名・BM 2名。担当エリアは GM が茨木・大和田・香里園、BM が枚方本院・田口山／交野・津田（氏名と所属院はシステムの管理者設定で登録。公開リポジトリには書かない） |
| 2 | 「マネージャー」 | その院の担当エリアの責任者（BM。BMのいない院は GM）として扱う。原文は変えず、該当項目に注記して GM確認 |
| 3 | アルバイト申請 | 社員が休日に追加で働くことを指す → 労働時間の通算・割増賃金の確認が必要（社労士確認）。MVP-2 で、確認が済むまで受付を止めておく |
| 4 | 法令確認 | 社労士に依頼する。「法令確認待ち」の項目は、社労士の名前と確認日を記録してから GM確認へ戻す |
| 5 | KPI | 既存のスプレッドシートから取り込み、スタッフ個人の数値は手入力で追加できるようにする（MVP-4） |
| 6 | 院長LINE | 当面は併用し、議事録・申請から順にシステムへ移す |

## 設計から変えた点（実装時）

- 状態（下書き〜公開）は項目ではなく**版ごと**に持つ。公開中の版を残したまま改訂版の承認を進められる
- DB はサーバーだけが接続し、`mn_` テーブルは RLS を有効にしてポリシーなし（ブラウザのキーでは一切読めない）。権限はサーバーの `authz.ts` で判定
- **このリポジトリは公開されている**ため、マニュアルの原文はリポジトリに置かず、管理者が画面から取り込んで DB にだけ保存する

進め方：Phase 1〜3（完了）→ **Phase 4 = MVP-1（完了）** → MVP-2 申請・残数 → MVP-3 院長ダッシュボード・議事録 → MVP-4 KPI・教育
