## 設計から変えた点（実装時）

- 状態（下書き〜公開）は項目ではなく**版ごと**に持つ。公開中の版を残したまま改訂版の承認を進められる
- DB はサーバーだけが接続し、`mn_` テーブルは RLS を有効にしてポリシーなし（ブラウザのキーでは一切読めない）。権限はサーバーの `authz.ts` で判定
- **このリポジトリは公開されている**ため、マニュアルの原文はリポジトリに置かず、管理者が画面から取り込んで DB にだけ保存する

## 評価に「報連相」と「期日もの」（2026-11-24）

| 場所 | 内容 |
|---|---|
| 月次評価（`lib/evaluation.js`） | 全員共通の「基本」に **期日もの（議事録・申請の期限）** を追加（報連相の次）。報連相に5段階の基準を書き、「約束・期限・ルールを守る」は「約束・ルールを守る」にして期限は期日ものへ |
| マニュアル（`lib/manual.js`） | 共通・社会人に「期日もの」を追加し、月次評価の期日ものと結びつけた。報連相の内容を行動マニュアル（遅刻等の連絡・院内トラブル・OD・週1報告）に合わせた |
| 育成カリキュラム | 新人（1ヶ月）に「期日もの（申請・届出）」、副院長（院長を目指す）に「院内会議の議事録」 |

- 期日ものの対象は、**院内会議の議事録（会議日の3日後の23:59・暦日）** と **申請・届出の事前提出**
- **有給休暇の取得や、急な病気などやむを得ない休みそのものは評価しない**（年休の取得を理由とした不利益な扱いにならないように。社労士に確認）
- 台帳のシートにすでに項目がある場合は、足りない項目を自動で足す。前の初期値のまま（誰も書き換えていない）説明だけを新しくし、書き換えてあるものは変えない
- 議事録・申請の仕組みができたら、期限内の割合を自動で入れられるようにする

進め方：Phase 1〜3（完了）→ 既存の /manual に寄せて段階的に追加（申請・残数 → 院長ダッシュボード・議事録 → KPI・教育）
