# あんど整骨院グループ 統合勤怠管理システム Ver.2.0

全7院（枚方本院・田口山院・津田院・交野院・茨木院・大和田院・香里園院）の勤怠・シフト・休暇を一元管理する Web アプリです。
設計書：[docs/DESIGN.md](docs/DESIGN.md)

## 技術構成

Next.js（App Router）/ TypeScript / Tailwind CSS / Supabase（Auth・PostgreSQL・RLS）/ Zod / Vitest / Playwright

権限は **画面・Server Action・DB（RLS）の三層** で判定します。最終的な防御は DB の RLS で、
判定ルールは `supabase/migrations/*_rls_helpers.sql` と `*_rls_policies.sql` にあります。

## セットアップ

### 1. Supabase プロジェクト

予約システムとは**別の Supabase プロジェクト**を作成してください（労務データを分離するため）。

```bash
# Supabase CLI でマイグレーションを適用
supabase init        # supabase/config.toml が無い場合のみ（既存の migrations はそのまま使われます）
supabase link --project-ref <project-ref>
supabase db push
# 初期7院と祝日（2026〜2027年）を投入
psql "<接続文字列>" -f supabase/seed.sql
```

### 2. 最初のシステム管理者を作る

1. Supabase ダッシュボード → Authentication → Users → 「Add user」でメール・パスワードを登録（Auto Confirm を ON）
2. SQL Editor で以下を実行（メールアドレスを置き換え）

```sql
insert into public.app_accounts (user_id, email, display_name)
select id, email, 'システム管理者' from auth.users where email = 'admin@example.com';

insert into public.user_roles (user_id, role)
select id, 'super_admin' from auth.users where email = 'admin@example.com';
```

以降のアカウント（本部事務・院長）は画面の「アカウント・権限」から作成できます。

### 共用端末の設置

1. 本部が「共用端末」で院を選んで登録コード（8文字・24時間有効）を発行
2. 各院のタブレットで `https://<ドメイン>/kiosk` を開き、登録コードを入力
3. スタッフ詳細の「共用端末のPIN」で各スタッフにPINを発行（初回の打刻時に本人が変更）
4. iPad のアクセスガイドなどで打刻画面以外を開けないように固定する

### 3. 環境変数

`.env.example` を `.env.local` にコピーして設定します。

| 変数 | 内容 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase の Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon（publishable）キー |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role キー（**サーバー専用**。アカウント作成・パスワード再設定に使用） |

### 4. 起動

```bash
npm install
npm run dev
```

### Vercel へのデプロイ

既存サイトとは別の Vercel プロジェクトを作成し、**Root Directory を `attendance`** にして、上記の環境変数を設定します。

### DB テスト

素の PostgreSQL 15 以上に対して、Supabase 互換の前提（`tests/db/supabase-shim.sql`）→ マイグレーション → seed を適用し、
`authenticated` ロール＋JWT を再現して RLS を検証します。各テストはトランザクション内で実行し、最後にロールバックします。

接続先は `TEST_DATABASE_URL`（既定 `postgres://postgres@127.0.0.1:54329/postgres`）。テスト実行時に `attendance_test` データベースを作り直します。

```bash
# 例：Docker で PostgreSQL を起動
docker run -d --name attendance-pg -p 54329:5432 -e POSTGRES_HOST_AUTH_METHOD=trust postgres:16
npm run test:db
```

主な検証内容：

- **必須テスト17**：院長は他院スタッフの個人情報を取得できない（応援登録スタッフも氏名・IDのみ）
- 院長兼務・異動・期限切れロール・停止アカウントの扱い
- 院長・スタッフはマスタを変更できない／本部は変更でき監査ログが残る
- 店舗名変更後も店舗IDと履歴が維持され、店舗・スタッフは物理削除できない
- 本部事務は本部・管理者ロールを付与・停止できない
- 監査ログは追記専用
- **必須テスト1〜4**：一般スタッフはシフトを編集できない／院長は担当外の院のシフトを編集できない／院長は担当院の確定シフトを理由付きで編集できる／変更前後が改訂ログに保存される
- シフトの日跨ぎ・院をまたぐ時間重複の禁止・楽観ロック・一括登録の全件ロールバック・締め済み月の変更禁止
- **必須テスト5〜7**：端末の認証セッションは打刻1回で失効し別人に引き継がれない（E2E では画面が自動で戻り氏名・トークンが残らないことも検証）／同じ打刻の再送・二度押し・順序誤りを防止／応援勤務は実際に打刻した院に記録
- PIN の bcrypt 保存・5回失敗ロック・推測しやすい PIN の拒否、打刻原本の追記専用、遅延送信の記録
- 勤怠計算：実働8時間、1日8時間超・週40時間超の法定時間外、深夜（日跨ぎ）、院の法定休日、所定休日、遅刻・早退・欠勤・打刻漏れ
- 打刻修正：院長申請→本部承認で原本に取消・追加を追記、二重承認の防止、確認後の再計算で確認取消
- **必須テスト8〜14・18**：振休の付与候補は付与対象者だけに生成／本部承認前は残数が増えず承認後に1日だけ付与／二重承認・同じ勤務実績への二重付与を防止（一意制約）／有給取得後に残数が減り、取消で戻る（二重返還なし）／付与後に勤怠が修正・取消されると不整合として検出
- 有給：申請中の予約残数、期限の近い付与から消化、失効処理、年5日取得義務、時間単位年休は労使協定設定時のみ、休暇承認時のシフト反映
- 振休：期限の変更（本部）、期限切れの失効、ポリシー無効時は正式付与しない、共用端末からの休暇申請、祝日の半日勤務（4時間以下）は0.5日
- 有給残数の取込：新規は移行として登録、取り込み直しは差分だけ調整、1行でも誤りがあれば全件取り消し（ファイルの読み取り・列名の表記ゆれ・和暦・Shift_JIS の CSV はユニットテスト）
- **必須テスト16**：本部は全院の勤怠を集計でき、院長は担当院のみ（`attendance_summary` は RLS が効く）
- 一括承認：院をまたいだ承認、承認履歴は1件ずつ同じ batch_id、失敗した1件だけ取り消して残りは承認、院長は実行不可。残数一覧は見られるスタッフのみ
- **必須テスト15**：月次締め後は打刻修正・シフト・休暇・勤怠の直接更新がすべて拒否され、遅れて届いた打刻は原本に残るが勤怠に反映しない。本部の理由付き再開で修正・再締めでき、履歴と締め時点の集計が残る
- 月次締め：院長確認前・月の途中・承認待ちがあると締められない、全院一括で締められない院だけ理由を返す、院長は他院の確認不可、帳票出力の監査ログ
- 帳票：CSV の引用符・改行・数式化防止、UTF-8 BOM、Shift_JIS（CP932）で機種依存文字（髙・﨑・①・㈱）が文字化けしない、Excel の数値・文字列、9帳票の集計と院長の出力範囲（ユニット）
- 休日管理：区分は本部のみ参照・登録（院長は不可）、「法定内」の日の勤務は法定休日労働・「法定外」は所定休日労働として再計算、締め済みの月は変更不可、変更・削除は監査ログ
- 代休：休日出勤から候補 → 本部承認で付与、期限は勤務日から1か月、「給与変換」の日は対象外、付与後に区分が変わると不整合として検出
- 有休の基準日方式：最初の付与日は入社6か月後以前、毎年同じ月日に法定日数（ユニット）
- 勤怠管理表の取込：区分・入社日・基準日・繰越の読み取り、管理表と同じ式での振休・代休の残り、表記ゆれ、出力した Excel をそのまま取り込める（ユニット）、取り込み直しても同じ結果・手入力は上書きしない（DB）
- 賃金管理：賃金・月の手入力・その監査ログは本部のみ参照可能（院長・スタッフ本人も不可）、適用開始月の履歴
- 残業代計算（ユニット）：月の合計の30分丸め、月給は基礎賃金÷月の所定時間・超過残業×1.25、時給・日給は×0.25、深夜×0.25、法定休日×0.35、月60時間超×0.25、交通費（月額／日額）、手入力の反映。賃金管理表の式からの読み取り
- 出勤簿形式の取込：「有給残」列の検出・氏名の照合・最新月シートの選択・入社日からの付与日推定（ユニット）、月末時点の残数への合わせ込み（DB）

### E2E テスト

既定では Supabase なしで、未ログイン時の保護とキオスク画面の分離を検証します。
`E2E_SUPABASE_URL` / `E2E_SUPABASE_ANON_KEY` と `E2E_HQ_EMAIL` / `E2E_HQ_PASSWORD` / `E2E_MANAGER_EMAIL` / `E2E_MANAGER_PASSWORD`
を設定すると、実際のログインを伴うテストも実行します。
