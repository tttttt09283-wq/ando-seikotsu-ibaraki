# Enejoy Hand AI部門 OS v0.1

株式会社Enejoy Hand のAI部門を動かすアプリです。統括責任者（岩永 拓己）が**司令塔**に指示を出すと、AI部門の司令塔とAI社員が実際に仕事を進めます。

- 会社：株式会社Enejoy Hand ／ 代表取締役：村上 大樹 ／ 企業理念：「心豊笑幸」
- AI部門のミッション：AIで業務を改善し、会社の土台を早急に作り上げる（重点テーマ：キャリア制度・評価制度の確立）
- MISSION 001：スタッフの評価基準とクラス（等級）を確定させる
- 売上目標：2026年7月〜2027年6月の年間売上 3億円（全部門合計）

> このフォルダは独立したアプリです。リポジトリ内の整骨院システム（ルートのHTML・`api/`・`body-check/`）と A.I.T company OS（`ait-company-os/`）には手を加えていません。データも別ファイル（`.data/enejoy-hand.json`）に保存します。

## 起動方法（Mac）

```bash
cd enejoy-hand-ai
npm install
npm run dev        # http://localhost:3001
```

Node.js 20.9 以上が必要です。環境変数は不要です（未設定なら **DEMO MODE**）。ログイン画面で「岩永 拓己」または「村上 大樹」を選び、「デモに入る」を押してください。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー（ポート3001。A.I.T company OS の3000と同時に起動できます） |
| `npm test` | テスト（Vitest） |
| `npm run typecheck` | 型チェック |
| `npm run build` / `npm start` | 本番ビルド / 起動 |

## 承認の仕組み

1. 承認が必要な行動（SNS投稿、外部送信、顧客への提案、契約、支払い・購入、予算変更、AI社員の追加、重要データの削除、外部サービスへの書き込み、スタッフ評価・クラスの確定）は、承認依頼として**まず岩永さんに届きます**。
2. 司令塔は、費用・相手・機密性から**推奨承認者（岩永／代表 村上）とその理由**を添えます（ルールは `src/tenants/enejoy-hand/approval-policy.ts`）。
3. 岩永さんは「承認・修正依頼・却下」を自分で行うか、「代表へ回す」を選びます。**評価・クラスの確定、契約、重要データの削除、30万円以上の支払いなど**は代表の決裁が必須で、岩永さんは承認できません。
4. 代表は `/president` で「承認・修正依頼・却下」を行えます。必須案件でなければ「統括責任者に任せる」こともできます。
5. 誰がいつ何をしたかは、承認ごとの記録と監査ログにすべて残ります。

## 数字（院別）の管理

管理の単位は**院（7院）**です。院ごとに、売上（目標・累計実績・着地予想・単価・LTV）、患者（新患・再診・総来院・レセ枚数・キャンセル率）、巻き爪、自賠、口コミの指標と、**全院合計**を月別に表示します（院・指標の定義は `src/tenants/enejoy-hand/numbers.ts`）。

年間売上3億円（2026年7月〜2027年6月）の**着地見込み**は「過ぎた月の実績＋今月の着地予想＋これからの月の事業計画」で計算します。

### 取り込み方法（「数字」画面の下部）

| データ | 方法 |
|---|---|
| 日計表（月ごとのGoogleスプレッドシート） | 月とURLを登録すると TOP シートを読み取ります（**読み取りのみ**）。アプリの起動中は、今月のファイルを5分ごとに自動で読み直します。過去の月は「登録した全月を読み直す」で再取得 |
| 日計表のCSV | TOPシートを「ファイル → ダウンロード → カンマ区切り形式（.csv）」で保存して取り込み（7〜9月の確定分などに） |
| 事業計画書 | Excel を CSV で保存して取り込み（「7月」「8月」…の見出し行と、院・損益の行）。Shift_JIS／UTF-8 どちらでも可 |
| 手入力 | 日計表がない月・院の補完用 |
| POS（サロエボ2） | CSVの項目を確認してから対応（患者個人の情報は取り込まない） |

日計表は、見出しの文字（「累計実績」「新患数」「巻き爪（売上）」など）で列を特定し、院名（「本院」「田口山」など）で行を特定します。列の並びが変わっても読めますが、見出しや院名の書き方が変わったら `numbers.ts` の aliases を直してください。

### Googleスプレッドシートの接続（推奨：サービスアカウント）

今の日計表は「リンクを知っている全員」に共有されており、URLを知っていれば誰でも経営数値を見られます。次の手順で、アプリ専用のアカウントだけが読める形に切り替えることをおすすめします。

1. Google Cloud コンソールでプロジェクトを作り、「Google Sheets API」を有効にする
2. 「サービスアカウント」を作成し、鍵（JSON）を作成してダウンロード（例：`~/enejoy-keys/sheets.json`。リポジトリの中には置かない）
3. 各月の日計表を、サービスアカウントのメールアドレス（`…@….iam.gserviceaccount.com`）に「閲覧者」で共有し、リンク共有は「制限付き」に戻す
4. `enejoy-hand-ai/.env.local` に `GOOGLE_SERVICE_ACCOUNT_KEY_FILE=/Users/（ユーザー名）/enejoy-keys/sheets.json` を書いて、アプリを再起動

設定しない場合は、公開リンク（CSVの書き出し）で先頭のシート（URLに `#gid=` があればそのシート）を読みます。

## 口コミ・Googleビジネスプロフィール・地域の競合

「口コミ・MEO」画面で、7院の口コミと Googleマップでの見つけられやすさ、近隣の競合を管理します。

| できること | 仕組み |
|---|---|
| 口コミの取り込み（星・本文・返信の有無） | Googleビジネスプロフィール API。6時間ごとに自動で読み取り |
| 院別の集計 | 星の平均・件数・今月の新着・未返信（★2以下は強調）・返信率・返信までの日数 |
| 口コミへの返信 | 返信案（DEMOではテンプレート）→ 内容を確認・修正 →「承認を依頼」→ 承認されたら Google に投稿。投稿の結果は承認の記録に残る |
| 表示回数・電話・ルート検索・ウェブサイト・予約 | Business Profile Performance API（月別・院別・前月比） |
| 地域の競合 | Places API (New) で検索して登録し、星・口コミ件数を1日1回取得。名前の手入力と、人が確認した数字の「記録」もできる |
| 司令塔との連携 | 「口コミと競合の状況を整理して」で分析・打ち手・返信ルールのTask。「今日の仕事を報告して」に未返信の件数が入る |

- **返信は外部への書き込み**なので、必ず承認を経てから投稿します（承認画面で代表へ回すこともできます）。DEMO（架空）の口コミには投稿しません。
- 口コミの投稿者名・本文はお客様の個人情報を含みうるため、このパソコンの `.data/` にだけ保存し、外部のAIには送りません。代表には表示しません。
- Places API で取得した競合の数字は、Google Maps Platform の利用規約に合わせて **30日で自動的に消します**。長期の推移は「記録」（人が Googleマップで確認した数字）と、自院のプロフィールの数字で残します。
- Googleの準備ができるまでは「接続・設定 → デモデータを作る」で、架空のデータで画面と流れを確認できます。

### Googleビジネスプロフィールの接続（初回のみ）

1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作成（日計表用と同じでよい）
2. 次の API を有効にする：My Business Account Management API／My Business Business Information API／Google My Business API／Business Profile Performance API
3. **ビジネスプロフィール API の利用申請**を行う（Google の「GBP API access request」フォーム。承認まで数日〜数週間かかることがあります。承認されるまで API の利用上限は 0 です）
4. 「OAuth 同意画面」を作成し、「認証情報 → OAuth クライアント ID（ウェブアプリケーション）」を作成。承認済みのリダイレクト URI に `http://localhost:3001/api/google/callback` を登録
5. `enejoy-hand-ai/.env.local` に `GOOGLE_OAUTH_CLIENT_ID` と `GOOGLE_OAUTH_CLIENT_SECRET` を書いてアプリを再起動
6. 「口コミ・MEO → 接続・設定 →『Googleアカウントで接続』」を押し、**院のプロフィールのオーナー（または管理者）のGoogleアカウント**でログインして許可
7. 読み取ったプロフィールと院の対応を確認（名前から自動で対応付けます）

接続の鍵（更新用トークン）は `.data/google-oauth.json` に保存され（所有者だけが読める設定・Gitには含まれません）、画面やAIには出しません。「接続を解除」で Google 側の許可も取り消します。

### 地域の競合（Places API）

1. 同じ Google Cloud プロジェクトで「Places API (New)」を有効にし、請求先アカウントを設定（月の無料枠があります）
2. 「認証情報 → APIキー」を作成し、使える API を Places API (New) に制限
3. `.env.local` に `GOOGLE_MAPS_API_KEY=…` を書いて再起動

## DEMO MODE とデータの区別

- AI部門の成果物・稼働状況・AIコストにはすべて `mode: "demo"` が付き、画面には「DEMO」「推定」と表示されます。成果物の数字はすべて架空です。
- **院の数字**（日計表・事業計画書・手入力）は本番の数字として別に保存し、デモの成果物の数字は入りません。取り込み・登録・手入力はすべて監査ログに残ります。「デモを最初からやり直す」を実行しても院の数字は消えません。
- 数字はこのパソコンの `.data/` に保存され（Gitには含まれません）、外部のAIには送信しません。
- 「代表の決裁で確定」のマイルストーンは、代表が実際に承認した記録があるときだけ達成になります。

## 安全対策

1日・月間のAI予算上限、同時実行数（全体・社員ごと）、社員ごとの1日のTask上限、1日の指示数・同時進行の指示数の上限、1指示あたりのTask上限、再試行の上限（指数バックオフ）、レビュー差し戻しの上限、1回の処理サイクルの遷移数上限、連続エラー時の安全停止、処理リース（二重実行の防止）、送信IDによる二重送信防止、監査ログ。

認証：役割（統括責任者／代表）ごとの署名付きCookieセッション、`proxy.ts` と各APIでの二重確認、代表は代表用画面と承認APIのみ利用可、同一オリジン確認、入力のZod検証、ログイン試行の制限。本番データを扱う前に `OPERATOR_PASSCODE`・`PRESIDENT_PASSCODE`・`SESSION_SECRET`（32文字以上）を設定してください。

## 個人情報の取り扱い

- 患者さんの健康・施術に関する情報は要配慮個人情報です。DEMO MODEでは架空のデータのみを使います。
- 実データを扱う前に、アクセス制御・保存先・外部AIへの送信範囲を説明し、代表 村上の承認を得ます。
- スタッフ評価に関わるTaskには「機密」の印が付きます。将来、評価データを保存する際は、閲覧者を本人・評価者・代表・統括責任者に限定します。
- Enejoy Hand の患者情報・スタッフ情報・経営数値は、社外資料や A.I.T company 側のデータに流用しません（事例化は代表の承認後、匿名化・数値加工のうえで行います）。

## 既存システム（あんど整骨院）との関係

リポジトリ内の予約・会計（POS）・カルテ・マイページのシステムは、Enejoy Hand の**一部の院で使用中**です（ヒアリング結果）。将来の連携で取得できそうなデータ（Supabase のテーブル）は次のとおりです。**連携の実装は代表の承認後に行います。**

| データ | テーブル | 取れそうな指標 |
|---|---|---|
| 予約 | `bookings` | 予約数・来院数・新患数・キャンセル・次回予約率・来院経路 |
| 会計 | `payments`・`refunds`・`payment_corrections` | 売上（保険／自費・支払方法・担当者別）・返金 |
| 回数券 | `passes`・`pass_usages` | 回数券の販売・消化 |
| スタッフ | `clinic_staff`・`staff_weekly_shifts` など | スタッフ数・稼働・スタッフ別KPI |
| 店舗 | `stores` | 院別の集計 |
| 口コミ | `review_snapshots` | 口コミ件数・評価の推移 |

患者個人の情報（カルテ・問診）は連携の対象外とし、集計値だけを読み取る設計を想定しています。システムを使っていない院は、手入力（将来はCSV）で月次の実績を記録します。
