# 02. 要件定義書（Phase 1 ドラフト）

## 1. 目的

顧客へのフォロー漏れを防止し、来店後の関係維持と再来店につなげる。
「誰に・いつまでに・何をするか」を毎日自動で提示し、対応結果を記録する。

## 2. 対象範囲

### 2.1 Phase 1 に含める

- マルチテナント（組織 → 店舗 → スタッフ）と4ロールの権限管理
- 顧客管理（登録・編集・検索・絞り込み・タグ・CSV取込・エクスポート・削除）
- 来店履歴・予約情報の記録（手入力・CSV）
- 連絡同意・配信停止の記録（履歴つき）
- フォロールール設定と、フォロータスクの自動抽出（日次＋手動実行）
- タスクの割当・期限・ステータス管理・対応記録
- メッセージテンプレート（編集・複製・クリップボードへのコピー）
- ダッシュボード・分析
- 監査ログ

### 2.2 Phase 1 に含めない

- LINE Messaging API / Webhook / LINEログイン / LINE からの自動送信
- メール・SMS 等の外部送信全般
- 課金・請求
- 予約システム・POS との自動連携
- 医療情報・詳細な症状情報の管理

## 3. 機能要件

### F1. 認証・アカウント
- メール＋パスワードでログイン（Supabase Auth。パスワードはアプリ側で保持しない）
- パスワード再設定、招待受諾
- 管理者ロールは MFA 必須（01 Q17）
- 複数組織に所属する場合は組織切替

### F2. ダッシュボード
- 今日のフォロー対象 / 期限切れ / 未対応件数 / 完了件数（当月）/ 顧客数 / 再来店確認数（当月）
- 店舗別の対応状況（未対応・期限切れ・完了率）
- 表示範囲はロールに従う（Staff は自分の担当＋所属店舗）

### F3. 顧客一覧
- 表示：氏名・顧客番号・所属店舗・最終来店日・次回予約日・担当スタッフ・フォロー状況・タグ
- 検索：氏名（漢字・かな）、顧客番号、電話番号（部分一致）
- 絞り込み：店舗・担当・タグ・フォロー状況・最終来店からの日数・連絡可否・予約状況
- 次回予約日が無い場合は **「予約未確認」** と表示（「予約なし」とは表示しない）

### F4. 顧客詳細
- 基本情報 / 来店履歴 / 予約情報 / フォロー履歴（タスク・連絡記録）/ 担当者 / 対応メモ / 連絡同意・配信停止状態
- 連絡不可・配信停止の顧客はヘッダーに明示（赤バッジ）

### F5. フォロータスク
- ルールに基づく自動抽出（06 参照）、手動作成
- 担当者割当（ルール既定：顧客の担当 → 店舗責任者 → 未割当）
- ステータス：**未対応 / 対応済み / 保留 / 対象外**
- 対応記録：連絡手段・結果・内容・使用テンプレート
- 同一顧客・同一ルール・同一対象期間の重複生成を DB 制約で防止
- 連絡不可・配信停止の顧客は連絡タスクを生成しない（既存の未対応タスクは自動で対象外）

### F6. メッセージテンプレート
- 初期テンプレート5種（初回来店お礼 / 状態確認 / 次回予約案内 / 未来店者案内 / 季節のご挨拶）を組織作成時に投入
- 編集・複製・アーカイブ、差し込み変数のプレビュー、ワンタップでコピー
- **外部送信は行わない**。スタッフが別ツールで送信後、手動で対応記録を残す

### F7. 分析
- フォロー対象件数 / 対応完了率 / 期限超過件数 / 予約確認数 / 再来店確認数 / 店舗別実績
- 期間指定（今月・先月・任意期間）
- 「フォロー後○日以内に予約・来店の記録があった件数」として表示し、
  **フォローによって発生したとは表現しない**（画面に注記を常時表示）

### F8. 設定
- 会社情報 / 店舗情報 / スタッフ管理（招待・無効化・ロール変更）/ 権限一覧 / フォロー条件 / テンプレート管理 / 監査ログ閲覧 / データ管理（エクスポート・削除）

### F9. Platform Admin
- 組織の作成・停止、Organization Admin の招待、利用状況（件数のみ）の閲覧
- **顧客個人情報は閲覧不可**

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応端末 | スマートフォン優先（幅 360px〜）、タブレット・PC 対応 |
| 性能 | 顧客 1万件／組織で一覧表示 1 秒以内（インデックス設計で担保） |
| 可用性 | Vercel＋Supabase のマネージド構成。業務時間外のメンテナンス |
| セキュリティ | RLS＋サーバー側認可の二重防御、監査ログ、CSRF/XSS 対策（05・07 参照） |
| 個人情報 | 最小限の項目、エクスポート・削除に対応、テストは架空データのみ |
| 環境分離 | 開発・本番で Supabase / Vercel 環境変数を分離 |
| 言語 | 日本語 UI、タイムゾーン Asia/Tokyo（組織単位で保持） |
| アクセシビリティ | タップ領域 44px 以上、コントラスト比 4.5:1 以上 |

## 5. 用語

| 用語 | 定義 |
|---|---|
| 組織 | 契約単位の企業（例：○○整骨院グループ） |
| 店舗 | 組織に属する店舗・院 |
| フォロールール | タスクを自動抽出する条件 |
| 対象期間キー | 重複防止に使う「どの出来事を起点にしたタスクか」を表す値（06 参照） |
| 再来店確認 | フォロー対応後に来店記録が登録されたこと（因果関係は示さない） |
| 予約確認 | フォロー対応後に予約記録が登録された、またはスタッフが予約ありと記録したこと |
