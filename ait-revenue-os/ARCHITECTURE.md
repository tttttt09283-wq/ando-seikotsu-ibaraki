# A.I.T Revenue OS — 設計

## 全体像

```
┌──────────── Streamlit 画面（revenue_os/ui/）────────────┐
│ ダッシュボード 市場調査 note商品 楽天商品 コンテンツ 承認キュー CSV取込 チャド報告 │
└───────────────┬───────────────────────────────────────┘
                │ 画面は「業務ロジック」だけを呼ぶ
┌───────────────▼──────────────── 業務ロジック ───────────────┐
│ workflow.py   承認ワークフロー（状態遷移・人間のみ承認・公開はURL記録のみ）│
│ quality.py    品質ルールチェック／公開前チェックリスト                  │
│ csv_import.py 列マッピング・円の解析・重複防止                         │
│ kpi.py        KPI集計（note・楽天を分けて集計し合算）                  │
│ report.py     チャド日次報告（実績＝DB集計／提案＝AI仮説）              │
│ seed.py       サンプルデータ（is_sample で区別・一括削除）              │
│ ai/           AI社員：client.py（API／テンプレート切替・費用記録）       │
│               roles.py（共通ルール）・generators.py（役割ごとの生成）    │
└───────────────┬──────────────────────────────────────────┘
                │ SQLAlchemy 2.0
┌───────────────▼──────────────┐      ┌──────────────────────┐
│ SQLite  data/ait_revenue.db  │      │ Anthropic API（任意） │
│ db.py：番号付きマイグレーション │      │ キーは .env のみ      │
└──────────────────────────────┘      └──────────────────────┘
外部サービス（note・楽天・SNS）へは一切接続しない
```

## データモデル

| テーブル | 役割 | 要点 |
|---|---|---|
| research_themes / research_sources | 市場調査 | `hypothesis`（仮説）と `verified_facts`（確認済み）を別列で保持。出典は人間が登録し確認日時を持つ。「確認済み」には出典1件以上が必要 |
| note_products | note商品 | 企画・無料記事・有料記事・価格・導線・CTA・公開URL。「販売中」には公開URLが必要 |
| rakuten_items | 楽天商品（手動登録） | 価格・報酬率・在庫それぞれに出典URLと確認日時。値を入れるときは出典と日時が必須 |
| contents / content_revisions | コンテンツ | 下書きの間だけ編集可。保存ごとに修正履歴 |
| approval_events | 承認の記録 | 誰が・いつ・どの状態へ・チェックリスト内容 |
| sales_records / import_batches | 売上 | 金額は円の整数。`(source, dedupe_key)` に一意制約。受取額＝note:売上−手数料、楽天:成果報酬 |
| channel_metrics | CTR/CVR 用指標 | 管理画面の数値を手入力 |
| expenses / ai_usage | 費用 | AI利用は推定費用を毎回記録（テンプレートは0円） |
| tasks / daily_reports | チャド | 報告は「実績」「提案（仮説）」「優先タスク」を別列で保存 |

サンプルデータは全テーブルで `is_sample=True`。集計から除外・一括削除できる。

## 承認ワークフロー

```
下書き ──レビューに出す──▶ レビュー待ち ──承認（人間・チェックリスト全確認）──▶ 承認済み ──公開URLを入力（人間）──▶ 公開済み
  ▲                         │  └─却下（理由必須）─▶ 却下 ──作り直す──┘                │
  └──────差し戻し（理由必須）─┴──────────────────────────────────────────────┘
```
- 承認・却下・差し戻し・公開記録は `社長` のみ。AI役割名では例外になる。
- 品質ルールで「要修正」（例：アフィリエイトなのに広告表記なし、DM誘導）があると承認できない。
- 承認は状態の変更のみ。公開処理は存在しない。

## AI の扱い

- `ai/client.py` が唯一の API 呼び出し口。`client.beta.messages.create` に JSON スキーマ（`output_config.format`）を渡し、構造化された結果を受け取る。拒否時のサーバー側フォールバック（`fallbacks: "default"`）を有効化。
- テンプレートに切り替わる条件：APIキーなし／1日の予算超過／認証・通信・API エラー／拒否／JSON不正／出力上限。
- 全役割の system プロンプトに共通ルール（架空のレビュー・体験・売上・効果・URLを作らない、仮説と事実を分ける、広告表記、DM・スパム禁止）を入れる。
- AIの出力は「下書き」または「仮説」欄にのみ保存され、承認を経ないと公開対象にならない。

## マイグレーション

`db.py` の `MIGRATIONS` に番号付きの手順を追加する方式。起動時に未適用分だけを適用し、既存DBは適用前に `data/backups/` へ自動コピーする。既存の手順は書き換えない。
