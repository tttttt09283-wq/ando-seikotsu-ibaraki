# FREEDOM OS

**AI × 鍼灸・整体｜個人独立シミュレーション＆マンダラ行動管理システム**

> 夢を数字に、数字を行動に、行動を独立につなげる。

81マスのマンダラチャート・独立収益シミュレーション・タスク・ロードマップ・独立判定・週間レビュー・AI経営参謀を、**1つのデータとしてつないだ**個人用の経営管理アプリです。
「自分が独立するために、何を、いつまでに、どれだけ達成すればいいか」を毎日確認できます。

> このフォルダは、あんど整骨院の業務システム（リポジトリ直下）とは**別のアプリ・別の Vercel プロジェクト・別の Supabase プロジェクト**です。
> 個人の経営データを勤務先のデータと混ぜないため、データベースも必ず分けてください。

## 1. 主な機能

| 画面 | できること |
| --- | --- |
| ダッシュボード | 本業収入・施術／AI売上・経費・事業利益・推定手取り・目標との差額、過去6か月の実績＋今後6か月の試算、独立準備（条件・生活防衛資金・顧客基盤・収益安定性・準備進捗・独立日まで）、今日の最重要1＋補助2、今週の達成率、遅延、マンダラ進捗、AI分析 |
| マンダラ | 9×9（81マス）／領域ごと表示、色＋文字のステータス、詳細編集（14項目）、**現在の数字と必要な施術件数・顧客数・不足・関連行動・期限・達成見込み**、行動計画の自動生成、Excel／CSV 取り込み（プレビュー・列の対応付け・既存を上書きしない）、CSV 書き出し |
| 収益シミュレーター | 施術・AI・全体収支の計算、3シナリオ（保守・標準・挑戦）の保存と36か月比較、独立予定日からの逆算 |
| 月次実績 | 売上・経費・施術指標・AI指標・家計を月ごとに入力（シミュレーションとは別保存）、CSV 入出力 |
| タスク | 長期→年間→四半期→月間→週間→今日の階層、マンダラ項目と ID で連携、依存関係、今日の提案（所要時間の上限内） |
| ロードマップ | 年・四半期・月・週の切替、領域別目標・マイルストーン・タスク・進捗・遅延・依存関係（矢印） |
| 独立判定 | 7条件を「達成／未達／データ不足／要確認」で個別判定（成功確率は出さない、退職を自動で推奨しない） |
| 週間レビュー | 毎週の振り返りを履歴保存、先週比・先月比（4週合計）・目標比 |
| AI経営参謀 | Claude API をサーバー経由で利用。キー未設定でもルールベースで動作。提案は承認したものだけタスク化 |
| 設定・データ | 目標値・判定基準・税負担率などの変更、JSON バックアップ／復元、各種 CSV、全削除、監査ログ |

### データの連携（中心の考え方）

```
月次実績（実データ） ──┐
                       ├─→ マンダラ KPI（自動取得）─→ 進捗・状態（達成／目標未達）
シナリオ（試算） ──────┤                         └→ 必要件数・顧客数・不足・達成見込み
                       ├─→ 独立判定（7条件）
タスク（ID で紐づけ）──┴─→ 今日の提案・週の達成率・ロードマップ
```

- 売上 KPI は**実績の入力でだけ**更新されます。タスクを完了しても売上目標は達成扱いになりません。
- 画面上の数字には「実績」「試算」「目標」「計算」のラベルを付けて区別しています。

## 2. 技術構成

Next.js 16（App Router）／TypeScript／Tailwind CSS v4／shadcn/ui（radix-ui ベースのコンポーネント）／Recharts／Supabase（PostgreSQL・Auth・RLS）／Zod／React Hook Form／date-fns／Anthropic SDK／Vitest

```
freedom-os/
├─ supabase/migrations/      DB スキーマ（18テーブル・制約・RLS・トリガー）
├─ samples/                  取り込みテスト用のサンプル CSV
├─ docs/                     設定手順・操作マニュアル・今後の拡張案
├─ src/lib/domain/           計算エンジン（純粋関数・テスト対象）
│   ├─ calc.ts               施術・AI・全体収支・コホート・逆算の基本計算
│   ├─ projection.ts         シナリオの月次予測（36か月）と独立条件の見込み
│   ├─ actuals.ts            月次実績の集計
│   ├─ mandala.ts            マンダラの進捗・状態・KPI 自動取得
│   ├─ criteria.ts           独立判定エンジン（7条件）
│   ├─ tasks.ts              今日の最重要1＋補助2、週の達成率、依存関係
│   ├─ generator.ts          行動計画の自動生成
│   ├─ model.ts              全データを束ねる計算モデル（画面共通）
│   ├─ advisor.ts            AI に渡す最小限データ／ルールベース分析
│   └─ template.ts           初期マンダラ（64行動）・マイルストーン・判定条件
├─ src/lib/io/               CSV・マンダラ（9×9／一覧）の入出力
├─ src/lib/server/           ストア（Supabase／ローカル JSON）・監査ログ・業務処理・AI 呼び出し
└─ src/app/                  画面（(app) 配下）・Server Actions・API（/api/export）
```

## 3. ローカルで起動する

必要なもの：Node.js 20.9 以上

```bash
cd freedom-os
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。

- **Supabase を設定していない場合**は「ローカルモード」で動きます（ログインなし・データは `freedom-os/.data/` の JSON に保存。開発専用で、`.gitignore` 済み）。
- Supabase を使う場合は `.env.example` を `.env.local` にコピーして値を設定してください（手順は [docs/setup.md](docs/setup.md)）。
- 本番ビルドをローカルで試すとき：`npm run build` → `FREEDOM_ALLOW_LOCAL_MODE=1 npm start`（Vercel 上ではローカルモードは常に無効）。

## 4. テスト

```bash
cd freedom-os
npm test          # 自動テスト（Vitest）
npm run lint      # 型チェック（tsc --noEmit）
```

テストの範囲（76件）：

- 施術売上・AI 月額売上・事業利益・税社保の概算・家計残高の推移
- 仕様の基準ケース：単価 10,000円 × 80件 = 800,000円、AI 月額 50,000円 × 6社 = 300,000円 ＋ 商品 100,000円 = AI 400,000円、全体月商 1,200,000円
- 解約率を反映した契約数推移、患者の月次コホート、必要患者数・必要新患数・必要 AI 契約数の逆算
- マンダラの進捗計算、タスクと KPI の連携（タスク完了だけで売上 KPI を達成扱いにしない）
- 独立条件の判定（達成／未達／データ不足／要確認）、今日の提案が実行可能時間を超えないこと
- 0除算・未入力値・不正値
- シナリオの保存と再読み込み、月次実績の保存と CSV 往復、マンダラ取り込み（既存を上書きしない）、バックアップと復元、外部キーの整合性、ユーザーごとのデータ分離、監査ログの不変性
- AI に送るデータに患者情報やメモが含まれないこと

## 5. デプロイ（Vercel）

1. Supabase で**個人用の新しいプロジェクト**を作り、`supabase/migrations/20261114000000_init.sql` を SQL Editor で実行
2. Vercel で新規プロジェクトを作成し、**Root Directory を `freedom-os`** に設定
3. 環境変数（Production / Preview）を設定：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`、`ALLOWED_EMAILS`（推奨）、`ANTHROPIC_API_KEY`（任意）
4. デプロイ → 表示された URL で新規登録 → ログイン

詳しい手順と確認項目は **[docs/setup.md](docs/setup.md)** にあります。

> リポジトリ直下の `.vercelignore` で `/freedom-os` を除外しているため、既存の予約管理システムのデプロイにこのアプリは含まれません。

## 6. セキュリティ・個人情報

- すべての主要テーブルに `user_id` を持たせ、**RLS で本人の行だけ**読み書きできます。親子関係は `(id, user_id)` の複合外部キーで、他人の行にぶら下げられません。`anon` ロールには権限を付与していません。
- AI の API キーはサーバーだけで使い、ブラウザには送りません（`NEXT_PUBLIC_` を付けない）。
- AI に送るのは事業 KPI・目標・判定結果・タスク名・週間レビューの課題欄だけです。**患者の氏名・症状・施術記録はこのアプリに保存しない設計**で、送信内容は「AIに送るデータを確認」で事前に見られます。
- 保存・更新・削除・取り込み・書き出しはすべて監査ログ（追記のみ）に残ります。
- `ALLOWED_EMAILS` を設定すると、指定したメールアドレス以外は利用できません。

## 7. 注意事項

- 将来予測はすべて**仮定に基づく試算**です。
- 税金・社会保険は「事業利益 × 概算負担率」の概算です。消費税・インボイス・青色申告・事業形態（個人／法人）による違いは画面に注意事項として表示しています。実際の判断は税理士・保健所など専門家に確認してください。
- 独立判定で条件を満たしても、このシステムが退職を推奨・決定することはありません。
